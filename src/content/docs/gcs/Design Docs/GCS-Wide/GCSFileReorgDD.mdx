## Background
The GCS Desktop Repo is unorganized. It is unclear what files every subteam is working on, old folders/files that should be deleted, etc. 

Examples:
- The top level has a lot of UI subteam files that are not relevant to GCS as a whole. 
- Software Integration has a separate python program that needs to be run among other things. (The start up is difficult)
- The set up is also complicated (must do things in order and it is not always sucessful) 
- Several files that should have been ignored by .gitignore that still exist in the repo

## Solution
Each team will reorganize the [gcs-desktop-app](https://github.com/ngcp-project/gcs-desktop-app) repo into a monorepo of submodules/folders. This will be expanded upon in each subteam's respective Design Doc.

- See [UI File Reorg DD](/gcs/design-docs/user-interface/)(TODO: update link once made)
- See [DB File Reorg DD](/gcs/design-docs/database/)(TODO: update link once made)
- See [SI File Reorg DD](/gcs/design-docs/software-integration/)(TODO: update link once made)
- See [Infra File Reorg DD](/gcs/design-docs/infrastructure/)(TODO: update link once made)

**This design doc will detail everything that does not belong to a single subteam.**

The top level of the repo will be reserved for GCS wide files/folders.

**There will be a new centralized:**
- **Setup:** This should execute all the required set up (dependencies, docker, etc) in the correct order. Should also check for the presence of and make a python virtual environment if there is not one.
- **Start:** This should execute all the required programs to easily start the GCS. If applicable, subteams should provide their own centralized start that can be executed by the gcs start process.
